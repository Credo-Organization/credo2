TEACHER & EVALUATOR DEFENSE SCRIPTS

Exact verbal answers to high-difficulty jury questions
❓ Why can't students or recruiters just use LinkedIn or GitHub?

The Defense: LinkedIn is an unverified honor system—anyone can claim to be a Senior Architect, so recruiters still waste weeks manually screening candidates. GitHub is a code storage tool for developers, not a recruitment platform; it doesn't tell a recruiter whether code was copied, farmed by a bot, or matches specific job requirements. Minskey bridges the two: we take raw GitHub code, run it through fraud and commit physics audits, and convert it into a tamper-proof credential employers can hire from with zero manual testing.

❓ What if a student uses ChatGPT to write all their code on GitHub?

The Defense: Our GitProof engine analyzes commit physics and code entropy. When someone copies code from ChatGPT without understanding, they typically commit huge blocks of syntactically complete code in minutes with zero iterative debugging, refactoring, or organic commit history. GitProof detects these unnatural commit physics and flags the repository as suspicious.

❓ What if your AI models hallucinate or disagree?

The Defense: That is why Minskey does not rely on a single model. We built a 3-model consensus engine (Google Gemini, Meta Llama-3, and Grok). A verdict is only certified if at least 2 out of 3 models independently agree. Furthermore, the AI evaluation is grounded in deterministic heuristics: if all external AI gateways fail, the system falls back to a mathematical AST keyword-overlap model.

❓ Why do you need both Next.js AND a Python FastAPI backend?

The Defense: It represents a clean separation of concerns: Next.js delivers bank-grade authentication, Supabase SSR queries, and high-performance user interfaces. FastAPI Python is purpose-built for heavy AI and data science compute: running LangGraph state machines, Git AST parsers, PyTorch math, and cryptographic Ed25519 verification.

❓ Is this legally compliant with privacy laws (GDPR, DPDP Act)?

The Defense: Yes, by design through Zero-Knowledge Blind Matching. Candidate profiles are stripped of all PII (name, gender, age, photo, college) before reaching matching algorithms. Furthermore, credentials belong to the student under W3C DID standards, meaning students have complete sovereignty over who they share their verification links with.
